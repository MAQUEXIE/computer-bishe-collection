# 07 智慧医院预约挂号

分时段挂号、停诊自动改约、候诊队列、病历与费用，就医流程数字化。

## 技术栈

- 后端：SpringBoot 2.7.18 + MyBatis 2.3.2 + MySQL 8（JDK8）
- 前端：Vue3 + Vite + Element Plus + Vue Router + Pinia + Axios
- 后端端口：**9007**；前端端口：**5107**（/api 代理到 9007）
- 数据库：**db_07_hospital**（utf8mb4）

## 创新点实现

1. **分时段号源**：每个医生按日期 × 时段（如 08:00-09:00）配置号源总数，挂号时 `booked_count+1` 原子占号（`UPDATE ... WHERE booked_count < total_quota`），余号实时展示。
2. **停诊自动改约**：医生/管理员将某时段排班标记停诊后，系统自动把该时段已挂号患者改约到同医生最近可用时段（无号时退到同科室其他医生），无可用号源则退号，并生成站内通知推送给患者。

## 实测修复的 Bug

1. **DoctorMapper 动态 SQL 缺 `<script>` 包裹**：`listPublic`/`listAll` 中的 `<if>` 动态 SQL 未包 `<script>`，MyBatis 直接当字符串拼进 SQL 报语法错误，管理员医生列表 500。已修复为 `<script>...</script>`。
2. **Pinia store 解析 localStorage 崩溃**：`JSON.parse("undefined")` 抛异常导致整页空白路由卡死。已加 `safeParse` 容错（空/"undefined"→null）。
3. **候诊队列状态显示 bug**：已完成接诊的患者在队列里仍显示"候诊中"。已按 REGISTERED/CALLED/COMPLETED/CANCELLED 分别显示对应标签与操作列。

## 已知限制

- 无登录态拦截器（前后端分离演示，前端 localStorage 存用户信息，请求带 userId），重启后端不影响前端登录态。
- 候诊队列按"当天 CURDATE() + 挂号顺序"模拟叫号，未做真实排队叫号硬件对接。
- 支付为演示流程（管理员确认收款即置 PAID），未接真实支付渠道。
- 号源改约策略：同医生优先，其次同科室其他医生；跨科室不自动改约。
